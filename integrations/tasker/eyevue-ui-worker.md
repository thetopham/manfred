# EyeVue staged ChatGPT UI worker

`eyevue-ui-worker.java.txt` is a Tasker **Java Code** action for the S25's Android 16 / Tasker 6.6.20 / ChatGPT 1.2026.244 interface. It requires Android API 33 or later. It uses Tasker's accessibility service to inspect all interactive windows and derives each tap from a freshly located control. It does not use AutoInput, fixed screen coordinates, a ChatGPT API backend, or a new chat action.

This worker is an experimental companion to the [receipt queue](README.md). The queue owns receipt state; the worker owns a separate one-shot UI ledger. Each installed phone/app combination requires supervised acceptance. Host tests do not establish device behavior; the controlled S25 result below covers this specific installation.

On the supervised S25, source SHA256 `fb46dc580d5577cf276053be69028f0182dbb36b06b6b1a6e59a3dc9dd3e2652` completed automatic native file selection and Send in a controlled known-receipt replay. Its attachment stage took 3,312 ms and observed Image count 0 → 1, validated internet, no upload/error controls, and active Live Voice, without a focus toggle. An independent fresh UI dump confirmed the new image/reply, no remaining draft/Send, and End still present. The device's UI-confirmation flag was then enabled through the exact proof guard. A second replay on the same source completed its attachment stage in **3,777 ms**, returned `send_confirmed`, and advanced the queue to **SENT automatically**, with Live End visible and no focus toggle/manual actions. Repeating the completed receipt returned `duplicate` with the saved full UI-worker result unchanged and no additional worker execution recorded. A fresh installed export recursively matched all **13 actions** (12 worker + 1 dispatcher) to the final bundle. These controlled replays are not uninterrupted-audio/server receipt guarantees; other installations retain the default-off flag until verified.

## Action inputs and ordering

The generated project uses the observed Java Code action schema: code 474, `se=false`, code in Str arg0, return variable `%mq_ui_result` in Str arg1, Int arg2=1. The worker also explicitly sets `%mq_ui_result` before returning the same JSON. Clear that local before each stage so an action error cannot reuse an earlier result.

1. The queue's `claim` action supplies `%mq_ok=1`, `%mq_status=claimed`, and `%mq_id`, `%mq_owner`, `%mq_uri`, `%mq_filename`, `%mq_bytes`, `%mq_width`, `%mq_height`, `%mq_sha256`.
2. Tasker's external **Launch App** action opens/reuses ChatGPT. Set `%mq_stage=prepare` and execute the Java Code. The code independently checks the local gate and the persisted queue's claimed owner. It verifies the granted MediaStore URI before operating the UI, then waits at most twenty seconds for validated internet while checking that the phone stays unlocked. Manfred can publish the receipt before its glasses Wi-Fi session finishes closing.
3. `prepare` reuses visible **End** voice state or taps **Start a voice conversation** in the current ChatGPT screen and waits for End. It refuses an existing **Remove** attachment draft. If the observed Camera/Photos/Files attachment popup is already open in one higher ChatGPT window, it rechecks that popup, dismisses it with one Back action, and waits up to three seconds for its Files control to disappear and the voice entry to remain. Unknown dialogs are not dismissed, and failed dismissal is not retried. It then opens **Attachment → Files → Upload files**, then finds the exact filename in Android DocumentsUI. It returns `prepared` before selecting any image.
4. Only a matching `prepared` result permits the queue's `begin_send`. Set `%mq_stage=attach_send` and require its fresh `%mq_status=send_permitted` output. The Java action independently checks that gate, persisted sending owner, and the same worker's prepared stamp, no older than 90 seconds.
5. The worker rechecks the receipt and actual URI, requires an unlocked phone and validated internet immediately before selection, then consumes the local permit, and writes `selection_attempted` to its durable ledger before selecting the file once. It waits for **Remove** and **Send Message**, requires a validated internet network, and invokes Send once through its verified clickable parent. After gated UI confirmation, it may tap Start a voice conversation once in the current chat and wait for End. A voice-resume failure does not undo the confirmed image result or retry Send. Any uncertain image result after selection holds the item. No UI action is automatically retried.
6. The glue calls `complete` only for matching `send_confirmed`, with both attempt flags true. It calls `hold` for other active outcomes. A stopped/crashed worker leaves claimed/sending state blocking another worker. Manual recovery must stop the old worker before resolving that queue item.

Both stages return `no_op` before reading image content or touching the UI if their action-local gate is absent. UI worker task collisions must reject a concurrent instance; the queue adapter is the sole writer of `%ManfredEyevueQueue`.

## Receipt and picker identity

The worker compares every action-local receipt field with the persisted owned item. It only opens the queue's exact `content://media/{external|external_primary}/images/media/<id>` URI. It requires MIME image/jpeg, matching display name and size, exact byte count and SHA256, and matching decoded dimensions. Reads are capped at 32 MiB with a ten-second deadline checked between stream reads; a blocking provider read itself is not forcibly interrupted. Dimensions are header-only decoded. Streams and cursors close on failures. A missing grant or changed image fails without a gallery-latest fallback.

The observed S25 picker is `com.google.android.documentsui`. Its search button is `com.google.android.documentsui:id/option_menu_search`; the editable `AutoCompleteTextView` is `com.google.android.documentsui:id/search_src_text`. Optional `%mq_picker_package`, `%mq_picker_search_id`, and `%mq_picker_input_id` override those defaults for a separately verified picker. Only Google's or Android's DocumentsUI package is allowed. Search uses **Show roots → Images**, verifies/requests input focus, then uses ACTION_SET_TEXT and ACTION_IME_ENTER after refreshing the focused field. A picker that does not support the latter returns `picker_search_submit_not_supported`; no blind Enter tap is substituted.

Normal grid rows may expose exact filename text. Compact search results instead expose a description beginning **exact filename + comma + space**, followed by size/time. The locator accepts those two forms only, rejects editable fields and **Preview the file ...**, and counts a described row plus its filename child as one result. Two distinct matching rows fail as ambiguous. For the normal grid, the matched filename is resolved through its ancestors to the verified clickable DocumentsUI `item_root`, and that tile must still contain the exact filename. It then invokes the native tile's ACTION_CLICK once; the observed injected gesture could complete while leaving the grid unchanged. There is no gesture fallback. The text footer itself is not tapped. The observed compact-grid filename-described clickable row is supported when there is no item_root ancestor. Preview icons, unknown or non-clickable containers, and changed tiles fail without a fallback. This identifies a picker result by its unique generated filename; the accessibility API does not expose the URI that ChatGPT eventually receives. No arbitrary recent image or cloud file fallback is used.

The Send resolver requires the nearest clickable ancestor of the exact **Send Message** control to be enabled, visible, non-editable, and in the ChatGPT package, with one Send Message descendant and no other nonempty visible labels. A composer containing other controls, duplicate labels, a stale node, or a disabled/wrong-package parent cannot be clicked. The worker waits up to five seconds, checking every 200 ms without UI actions, for this target to become ready before recording a Send attempt. It then rechecks ownership/network and freshly resolves the target again for one ACTION_CLICK, with no gesture fallback. A timeout after file selection holds the image without consuming a Send attempt. Other ChatGPT startup controls retain their gesture path.

An earlier real worker reported `send_clickable_parent_not_identified` before its Send action. Later UIAutomator checks were found to have retained stale XML after an idle-state error; those snapshots cannot establish the contemporaneous ancestor flags or that manual Send failed. A subsequent successful fresh dump confirmed the manual image send and active Voice. With the readiness change installed, a later automatic phone run successfully selected the exact file and invoked native Send, with Voice still active. The original transient-readiness versus service-tree explanation remains unproved. That run held because the observation step hid the transcript. The later controlled replay with the directional fix passed the complete positive UI predicate without toggling the already visible transcript.

## Results, evidence, and completion switch

Result JSON includes `version=1`, `stage`, `status`, `reason`, `step`, `id`, `owner`, `elapsedMs`, `selectionAttempted`, `sendAttempted`, completed-action/gesture flags, and voice/evidence fields. Native file selection reports `selectionMethod=accessibility_click` and `selectionActionCompleted` only when the action returns true; legacy `selectionGestureCompleted` remains false. Native Send similarly reports `sendMethod=accessibility_click`, `sendActionCompleted`, and `sendGestureCompleted=false`. A true native return is not proof of attachment or submission, so the separate preview and post-send evidence checks remain required. Status is `no_op`, `prepared`, `error`, `ambiguous`, or `send_confirmed`. Exceptions retain a bounded error type/reason; the worker does not collect message text or window titles. The full result is also written to `Tasker/manfred-ui-worker.json`. The generated glue summary in `Tasker/manfred-worker.json` preserves known voice booleans even when image status is held; absent or identity-invalid voice evidence is `null`, not false. This reporting does not change queue decisions. If a tap is blocked, `tapBlock` records only its requested selector, target window ID/layer/type/bounds, and obstructing window ID/layer/type/bounds/root package/active/focused flags. `tapAttempts` additionally records each actual target ID, bounds, clickable state, numeric action IDs, action role/method, native return and gesture completion. It retains no arbitrary accessibility action labels. `sendTarget` separately records at most eight refreshed Send ancestors with class/package, visibility/enabled/clickable/editable flags, bounds, numeric action IDs, and readiness/timeout metadata. It does not record their text or descriptions. The existing obstruction rule remains unchanged while this evidence is collected. Diagnostic-write failures are reported in the action result and do not trigger a UI retry.

After one accepted native Send action, the observation requires three consecutive samples with Remove and Send Message gone while a recognized voice entry/state is visible. `submissionObserved` records that UI transition. If End is visible but there are no Image nodes, the worker inspects the exact lowercase **toggle focus mode** control in its own app window. It only toggles once when that orb is at least half the window width, lies fully within the window, has End in the same window, and has no same-window Copy/Good response/Bad response/Read aloud controls. This is the observed large focused-orb layout. An orb narrower than half the window is classified as an already visible transcript and is left alone; conflicting or missing geometry also prevents a toggle. The worker records `focusedModeClassification` and `focusModeEvidence` (orb/window bounds, window ID, same-window voice and exact known transcript controls). The phone test showed that toggling the small orb hid a transcript despite successful automatic image submission; absence of an Image alone therefore never establishes focus direction. Within the existing fifteen-second post-send observation window, it waits for positive `newImageObserved` evidence and absence of **Uploading attachment**; an old Image alone does not end observation early; an observed upload error holds immediately. Revealing the transcript never selects Retry or repeats Send. It also records:

- `imagesBeforeSend` / `imagesAfterSend`: only Image-node counts, anonymous IDs, window IDs, bounds and diagnostic `nodeHashCode`. Node hashes never authorize completion.
- `newImageObserved`: an increased Image-node count, or a new unique ID when every previous image supplied an ID. Bounds changing alone is insufficient.
- `imageLocatorDiagnostic`: if the normal exact Image selector finds none, a separate read-only scan records exact-label candidates with window/bounds/visible/enabled flags. It does not authorize completion. Accepted Image nodes still require the ChatGPT package, exact Image text/description, visible and enabled state, and nonempty bounds. A later UIAutomator snapshot does not establish the native service tree at an earlier instant.
- `networkValidated`: Android reports the active network has internet and is validated. This does not prove reachability of ChatGPT's server.
- `errorUiObserved`: exact known English Retry, Try again, Something went wrong, Upload failed, Network error, Poor connection, Unsent · Retry, or Looks like some messages never sent. Retry? controls are present. Multiple Retry controls still count as an error; they are never clicked. It does not recognize every possible error presentation.
- `uploadInProgress` / `uploadObserved`: exact Uploading attachment is currently visible / was observed during this attempt. A pending upload prevents completion even if the composer cleared and an Image node appeared.
- `voiceState`, `voiceActiveBefore`, `voiceActiveAfter`, `voiceNeedsResume`. `voiceContinuity` remains `unverified`; accessibility state does not establish uninterrupted audio or a server conversation identifier. After gated UI confirmation it can resume voice once through the current chat's Start a voice conversation control, then observe End. It records `voiceResumeAttempted`, `voiceResumed`, and any `voiceResumeError`; `voiceActiveAfterSubmission` preserves the state before that recovery. It never navigates to another chat or resends an image to recover voice. UI continuity does not pin a conversation identifier, so concurrent manual navigation remains outside the verified workflow.

Initially leave **%ManfredEyevueUiConfirmed unset**. The first submission remains ambiguous/held while the supervised test checks the new photo and ChatGPT response. Once that installed UI predicate is verified, set the global to **verified_on_device_v1**. The same worker can then return `send_confirmed` only when all recorded submission/new-image/network/no-error checks pass and no upload is still in progress. This means **UI-confirmed submission, with no server receipt guarantee**. A changed app UI, an old indistinguishable image, or insufficient evidence still holds; the switch never enables automatic retries.

The separate **%ManfredEyevueUiLedger** stores only the current/last worker's id, owner, URI, filename, checksum, phase, elapsed timestamp, and initial voice flag. Phases are preparing, prepared, selection_attempted, send_attempted, submission_observed and ui_confirmed. Readback follows every ledger write. The local permit is changed to `ui_permit_consumed` before selection. Replaying the old owner cannot restart preparation or use a non-prepared ledger to attach again. Tasker globals plus collision settings are not a database transaction or an exactly-once guarantee across every OS failure.

## Source-file deployment

The installed phone's Java Code action successfully loads this authored worker with:

    return source("/sdcard/Tasker/Manfred/eyevue-ui-worker.java.txt");

Use that same body for both stages, retaining their existing stage/queue gates and return variable. BeanShell evaluates the file in the current namespace, preserving Tasker's helper and context objects. Replace the trusted local source only between worker runs and verify its hash; future code updates then do not require a whole-project reimport. This is a local executable source file, not a downloaded runtime command.

## Verification

The complete source is parsed by BeanShell 2.0b6. `test_ui_worker.py` executes the actual script against deterministic Tasker/Android fakes. Stage-flow tests replace the dispatch helper; focused target/native-action tests execute that production helper against fake Android nodes and verify one ACTION_CLICK with no gesture fallback for both the exact file tile and isolated Send parent. The current suite has 46 tests, including delayed/missing Send readiness, diagnostic flags, a late-arriving new Image, and full-window observation when only an old Image remains, small/conflicting orb rejection, and diagnostic-only disabled Image nodes. It covers receipt/URI failures, no-op gating, non-selecting preparation, existing drafts, exact picker labels and nested rows, ownership stamps, interrupted selection, stale permits, and completion evidence. The tests do not validate Android gesture callback delivery, real bitmap decoding, provider grants, search submission, or ChatGPT's installed UI.

An isolated runtime cache contains a checksum-verified Temurin 8u504 JRE plus bsh 2.0b6, org.json 20240303 and ECJ 3.26.0. No system installation is needed. Point the test at an existing equivalent cache:

    MANFRED_TASKER_JAVA_CACHE=/path/to/task-local-java-cache \
      python3 -m unittest discover -s integrations/tasker -p 'test_ui_worker.py' -v

On the phone, first run the entire Java action with `%mq_ok=0`; expect `no_op` and no UI/content access. Then test a new claimed receipt through prepare, inspect the exact picker result, and only then test the one-shot attachment stage. The initial all-window Files probe succeeded on an inactive ChatGPT popup while the underlying chat remained the active window; that validates the locating approach, not the entire workflow.

Tasker documents BeanShell, getVariable/setVariable, its accessibility-service helper and `implementClass` in the [Java Code reference](https://tasker.joaoapps.com/userguide/en/help/ah_java_code.html). Android documents the all-window API and callback-based gestures in [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), and selectors, bounds, text and IME actions in [AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo).
